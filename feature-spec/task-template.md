# <What needs doing, naming the file, function, column or config value>

## Context

Why this exists and what goes wrong without it. Two or three sentences.
Assume the reader was not part of the conversation this came from.

## Where to look

- `path/to/file:123` - what is there and why it matters.
- Link the spec or explanation doc that covers it in full, if one exists.

Enough for someone to open the right file and see the problem. Not a summary
of the code.

## Done when

- Short, checkable bullets.
- Behaviour, not implementation steps.

## Suggestion

What the fix might look like, in a few sentences. Hypothetical by definition:
a task is not a design, and whoever picks this up may well find a better shape
or discover this one does not work.

Say which way you lean and why. "No idea yet, needs investigating first" is a
real answer and better than inventing something to fill the space.

## Decided / Not decided

What was already settled and what is still open. Both can be one line.
"Nothing open" is a valid answer, and so is "not yet designed".
